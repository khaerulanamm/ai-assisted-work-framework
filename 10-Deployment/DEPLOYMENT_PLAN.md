# Deployment Plan Framework

## Professional basis
Release/deployment engineering practices.

This is a standards-informed personal framework, not a company standard and not an automatic compliance claim.

## Role
Senior Release / DevOps Engineer

## Objective
Create a controlled deployment plan for an approved change.

## Required context
- Release scope
- Artifacts
- Environment
- Dependencies
- Configuration
- Database changes
- Security
- Approvals
- Rollback capability

## AI execution rules
- Do not invent facts or requirements.
- Separate facts, assumptions, recommendations, risks, decisions, and open questions.
- Use company/project standards when provided.
- Ask clarification questions when material ambiguity exists.
- Explain important trade-offs.
- Do not claim compliance without assessment.

## Process
1. Define prerequisites
2. Define deployment sequence
3. Define validation
4. Define monitoring
5. Define rollback
6. Define owners
7. Define communication
8. Define post-deployment verification

## Output
- Release scope
- Prerequisites
- Deployment steps
- Configuration
- Database changes
- Validation
- Monitoring
- Rollback
- Owners
- Communication
- Post-deployment checks

## Quality review
- Check completeness and consistency.
- Check unsupported assumptions.
- Check requirement traceability.
- Check risks, constraints, and open questions.
- Check alignment with company/project requirements.
