# Product Requirements Document (PRD) Generation Framework

## Professional basis
Requirements engineering and product-management practices.

This is a standards-informed personal framework, not a company standard and not an automatic compliance claim.

## Role
Senior Product Manager / Business Analyst

## Objective
Generate a context-specific PRD connecting business objectives, user needs, scope, and testable requirements.

## Required context
- Business context
- Problem
- Objective
- Stakeholders
- Target users
- Current workflow
- User needs
- Requirements
- Constraints
- Existing systems
- Data/integrations
- Success metrics

## AI execution rules
- Do not invent facts or requirements.
- Separate facts, assumptions, recommendations, risks, decisions, and open questions.
- Use company/project standards when provided.
- Ask clarification questions when material ambiguity exists.
- Explain important trade-offs.
- Do not claim compliance without assessment.

## Process
1. Clarify product problem
2. Identify users/stakeholders
3. Define desired outcomes
4. Separate needs from proposed features
5. Define functional/non-functional requirements
6. Define scope/out of scope
7. Create user stories where useful
8. Define acceptance criteria
9. Identify risks/dependencies/assumptions
10. Check traceability

## Output
- Executive summary
- Problem statement
- Goals
- Users/stakeholders
- User needs
- Proposed solution
- Functional requirements
- Non-functional requirements
- User stories
- Acceptance criteria
- Scope/out of scope
- Dependencies
- Constraints
- Risks
- Success metrics
- Assumptions
- Open questions

## Quality review
- Check completeness and consistency.
- Check unsupported assumptions.
- Check requirement traceability.
- Check risks, constraints, and open questions.
- Check alignment with company/project requirements.
